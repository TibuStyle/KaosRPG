1. VISIÓN Y CORE LOOP
RPG web cooperativo con identidad/assets propios o licenciados. Siempre asíncrono
persistente. Director primero, jugadores por orden de unión, cola fija, circular
e ininterrumpible: no salto por desconexión, demora, fallo o reinicio. No hay selector
de ritmo. Host plantea escena, sin apertura automática IA facturable.
Acción trivial: commit narrativo final y avance. Riesgo: evaluación -> espera de
dados -> resultados guardados -> consecuencia final -> commit y avance.

3. CONTRATOS VIGENTES
CREACIÓN/PERSONAJES
Mantiene límites: host/jugador40, historia80, premisa2000, líneas rojas4000;
personaje60, historia requerida6000. Reglas magia high/low/none, tono epic/dark/comic,
mortalidad story/relentless; defaults high/epic/story. Random aún premisa fija.
Salas A-Z seis letras, únicas; unión solo lobby, ocho jugadores+host.
Aprobación exacta aprobado/mensaje_narrativo/perks/defectos; estados persistidos
 draft/evaluating/rejected/approved. Rasgos traits FK, nunca caché RAM privada.
Inicio solo host con al menos un jugador, todos conectados y aprobados.

EVALUACIÓN MECÁNICA
IA recibe mundo, 20 mensajes recientes, acción, rol y traits leídos de SQLite.
response_format json_schema strict con exactamente:
requiere_dado:boolean, narrativa_previa:string, dados_a_lanzar:string[],
cd_base:integer, modificadores:[{nombre:string,valor:integer,tipo:ventaja|desventaja}].
Narrativa1..5000. false exige dados=[], CD0, modificadores=[] y resolución final.
true exige CD1..100, notaciones NdS con N1..12 y S4/6/8/10/12/20/100,
máximo ocho grupos y doce dados totales. Solo rasgos existentes aplican ajustes,
uno por rasgo: ventaja+1..+5, desventaja-1..-5. Error IA conserva acción/turno.

REGLA MATEMÁTICA 1.5
CD final=clamp(1,100,cd_base-suma(modificadores)). Todos los dados SUMAN para una
única prueba. Éxito si total>=CD final. No se aplican bonos otra vez al resultado.
Ejemplo CD15/+3 => CD12. No doble d20, críticos automáticos, HP ni daño separado.
La IA puede elegir dados situacionales, pero no hay sistema de armas/combate formal.
La selección semántica/CD depende de IA; no se afirma balance garantizado.

UI Y DADOS 3D
Preparación persistente, notaciones, CD base/final, fórmula y ajustes verdes/rojos.
Etiquetas neutras Ajuste N preservan nombres de Perks/Defectos ocultos.
Solo autor actual puede pulsar Lanzar Dados. DiceBox lanza array exacto guardado,
espera onRollComplete y envía resultados individuales + total por Socket.io.
Módulo, workers, WASM y modelos locales bajo public/vendor generado por build.
Rutas origen/pathname relativas a import.meta.url compatibles con /repositorio/
de Pages. CSP worker-src self blob:, script-src wasm-unsafe-eval, offscreen=false.
Errores 3D dejan turno/configuración intactos; no inventar resultados como fallback.
Cliente persiste resultados completos en sessionStorage antes de enviar; ACK perdido
permite reenviar mismos números. Pestaña cerrada durante físicas, sin resultado
recibido, mantiene espera y permite nuevo lanzamiento al volver.

PERSISTENCIA Y RESOLUCIÓN
Migración transaccional user_version1->2 añade actions.stage, pending_roll,
roll_results; conserva DB1.4 y FK/cascadas. No bajar a servidor1.4 tras migración.
Estados: evaluation, awaiting_roll, resolution, done; status pending/failed/completed.
recover marca todos offline, evaluaciones de personajes draft, evaluation/resolution
interrumpidas failed. awaiting_roll permanece pending con mismo botón/configuración.
roll:submit {id,turnVersion,resultados:[{caras,valor}],total}: servidor valida autor,
versión, etapa, cantidades, caras/rangos y suma. Primer resultado válido se guarda
antes de segunda IA; iguales son idempotentes, diferentes se rechazan.
Segunda IA recibe acción, preparación, números, CD aplicada, ajustes neutros y
veredicto servidor. Responde {narrativa:string}. Mensaje público final con resumen
numérico, completed/done y avance se confirman en UNA transacción.
Fallo/reinicio en resolución: reintento explícito, mismos resultados, sin relanzar
ni reevaluar. No reintentos automáticos de coste, no exactly-once del proveedor.
Historial permanente, páginas100, snapshot últimos100, contexto IA20.
No hay chat paralelo, timeout, salto ni reordenación. Jugador playing solo ausentarse;
host puede cerrar/borrar sala. No TTL/expulsión automática ni borrar salas al apagar.

PRIVACIDAD, SEGURIDAD Y OPERACIÓN
Snapshot excluye historias, aprobación privada, nombres de rasgos, tokens/hashes.
Evaluación mecánica SÍ envía rasgos ocultos al proveedor; narración final no.
Prompt prohíbe revelarlos y redacción literal elimina nombres conocidos en narrativa.
No garantiza ocultación semántica/paráfrasis ni moderación de líneas rojas.
Token256 bits en sessionStorage; sessions SHA-256; no cuentas autenticadas.
WAL/FK/FULL/busy_timeout5000; SQLite fuera de public, volumen durable, una instancia.
Perder token puede bloquear partida. No multiinstancia/backups automáticos.
IA cuatro trabajos, tres/min miembro y diez/min sala; ahora dos llamadas por turno
arriesgado. Mantiene CORS, Origin WS, Helmet, límites HTTP y eventos.
IMPORTANTE: resultados generados por CLIENTE son manipulables. Validación de rango
y suma NO certifica azar. El servidor sí fija configuración, veredicto y avance.
Azar autorizado/verificable por servidor sigue pendiente; no presentar esto como
antitrampas. Memoria extensa, daño formal y balance completo tampoco se completan.
